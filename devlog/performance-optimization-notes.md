# 性能优化待办

分析时间：2026-06-07

## 当前瓶颈

7 Agent 串行 + 视频处理，单条广告 30-60s。

```
视频处理 (10-15s) → A1 (5-10s) → A2 (3-8s) → A3 (3-8s) → A4 (3-8s) → A5 (3-8s) → A6 (3-8s) → A7 (2-5s)
```

## 优化策略

| # | 策略 | 做法 | 预计节省 | 风险 |
|---|------|------|----------|------|
| 1 | A2+A3 并行 | Agent 3 去掉对 A2 的依赖（只需 A1 证据即可做用户心理分析），`asyncio.gather` 同时跑 | ~15-20% | Agent 3 可能缺少策略视角 |
| 2 | 上下文裁剪 | Agent 5/6/7 不传完整证据账本，只传摘要和 safe_claims，prompt 瘦身 40% | ~20-30% per call | 摘要可能丢失关键细节 |
| 3 | 小模型跑轻任务 | Agent 7（编辑元数据）和 publishing 评审用 haiku/mini 级别模型 | ~30-40% per call | 轻模型可能降低编辑质量 |
| 4 | 开 stream | 部分 agent 用 streaming 提前拿到 partial output | 感知延迟降低 | JSON structured output 不能 stream |

## 实施建议

- 优先 1+2，不改模型配置，纯代码优化
- 3 需要验证小模型在编辑任务上的质量
- 4 作为长期试验
