# Evidence-Driven Agent Report Design

## Goal

Make full-video Doubao understanding the primary analysis path, turn every important conclusion into an auditable evidence-backed claim, and deliver a polished editorial report that can be downloaded as Markdown or PDF.

## Product Principles

1. Full video is the primary source. `doubao-seed-2-0-lite-260215` must receive the downloaded video whenever one is available.
2. Facts, user context, and model inference are different classes of information and must never be silently mixed.
3. An unsupported claim is downgraded or removed, not polished into something more convincing.
4. Novelty comes from competing creative interpretations and explicit evaluation, not from exaggeration.
5. Web, Markdown, and PDF are three renderings of the same report rather than independently generated documents.

## Agent Architecture

### 1. Evidence Producer

Doubao inspects the complete video and returns:

- A time-coded evidence ledger.
- Verbatim or near-verbatim spoken/on-screen claims.
- Observed scenes, actions, product appearances, prices, and calls to action.
- Source quality and limitations.

When Doubao fails, the pipeline records the failure and uses extracted frames. Text-only analysis is the final fallback.

### 2. Strategy Analyst

The strategy agent receives the evidence ledger. Every strategic conclusion includes:

- `claim`
- `evidence_ids`
- `claim_type`: observed, inferred, or hypothesis
- `confidence`
- `counterpoint`

### 3. Audience Researcher

Audience conclusions are explicitly hypotheses unless the material contains direct audience evidence. Demographic certainty is prohibited when inferred only from category conventions.

### 4. Context Analyst

The context agent may describe durable category/platform patterns. It must not call a trend “current” unless current external evidence exists. Time-sensitive claims are marked unverified.

### 5. Factuality Auditor

An independent reviewer checks:

- Evidence IDs exist.
- Observed claims are actually supported.
- Inferences are labelled.
- Contradictions and overclaims are listed.
- A trust score and publication decision are returned.

Unsupported statements are excluded from publication context.

### 6. Scoring Analyst

Scores use anchored 1–5 rubrics and include a reason plus supporting evidence for each category. Missing evidence reduces certainty rather than automatically reducing creative quality.

### 7. Editorial Studio

Two editorial concepts are generated. A judge evaluates them twice with reversed order to reduce position bias, then selects or synthesizes the strongest version. Publication copy only receives audited context.

## Report Structure

1. Cover and executive takeaway.
2. Trust panel: score, source coverage, audit decision, limitations.
3. Evidence ledger with timestamps and IDs.
4. Creative scorecard with rationale.
5. Material anatomy.
6. Strategy claims.
7. Audience hypotheses.
8. Platform and cultural context.
9. Reusable creative blueprint.
10. Risks, unknowns, and validation ideas.
11. Douyin and Xiaohongshu publishing outputs.
12. Methodology and disclosure.

## Export Architecture

The backend builds a deterministic Markdown report from structured analysis. Markdown is converted to safe HTML and rendered with a dedicated print stylesheet. A PDF endpoint returns an attachment generated by WeasyPrint. The frontend exposes Markdown and PDF download actions beside the report.

## Failure Behavior

- Doubao failure is retained in `analysis_meta`, including model and fallback path.
- Audit failure does not fail the entire job; it marks the report as requiring review and suppresses unsupported publishing claims.
- PDF rendering failure returns an actionable HTTP error without affecting the saved analysis.
